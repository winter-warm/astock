# Python 与 C++ 的关键差异

## 已会编程，先调整对对象的理解
你不需要重学循环和条件判断。Python 最值得先掌握的是名字与对象的关系。赋值 a = b 通常让两个名字指向同一个对象，不会自动构造一份独立容器。对于列表，随后通过任一名字修改元素，另一名字都会看到变化。这一点对研究代码很重要：若把原始数据和实验副本混用，后一个实验可能悄悄改变前一个实验的输入。

C++ 的值复制、引用和指针需要从声明判断；Python 的普通赋值不会用不同声明区分它们。整数、字符串等对象不可变，列表与字典可变。数字加法会产生新值，不意味着列表元素赋值也会建立新列表。

## 切片与边界
prices[-3:] 取最后三个元素。prices[a:b] 包含 a，不包含 b，这与常见半开区间习惯一致。Python 的切片超过右边界通常会截断，而直接索引不存在的元素会抛出 IndexError。因此“没有报错”不能证明你拿到了足够长的历史窗口。计算 20 日均线前应检查长度，而不是对不足 20 个值的切片直接求平均。

负索引 -1 表示最后一个元素。当你在历史循环里对完整价格数组使用 prices[-1]，读取的是整份样本最后一天，不是循环所在当天。初学者常把这个语法便利误用成未来信息。

## 类型与运算
Python 的 / 是除法，5 / 2 得到 2.5；// 是向下取整，负数时与截断到零的思路不同。金融程序里还会遇到 float 与 Decimal：float 存在二进制近似误差，金额与规则计算不能随意混用两者。AStock 账户内部使用精确金额对象，输出指标时常转为 float；转换时机应明确。

字典按键取值很方便，但拼错键会抛出 KeyError。get 可以提供默认值，却不应把关键字段缺失都默认为零，否则错误数据会变成看似合理的低价格或空持仓。关键输入应明确校验。

## 推导式与可读性
例子里的 returns 用列表推导式表达“对每个相邻价格算收益”。它适合短且纯粹的转换。不建议把下单、日志与状态更新塞进推导式；这些有副作用的步骤用普通循环更容易核对。不要为了看起来像 Python 而牺牲研究过程的可追溯性。

## 参考答案

1. 断言会失败，这正好说明两个名字共享列表。
2. 副本也会变化，因为内部列表仍共享；需要按用途逐层复制或使用 deepcopy。
3. prices[i-1] 在 i=0 时访问最后一个价格，不会越界报错，却形成错误的首期收益。这是应特别防范的静默逻辑错误。
