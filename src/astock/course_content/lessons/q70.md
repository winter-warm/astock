# 建立评估流程：让计算结果约束研究，而不是让模型评价自己

## 评估角色的工作应当可重复
代码 agent 提交了一个候选表达式，下一步不是问语言模型“你觉得它好吗”，而是在固定数据与规则下计算结果。评估角色应负责验证输入、执行已审阅代码、计算指标、保存日志并指出不足。语言模型可以帮助解释报告，但不能替代这些确定性计算。

本课比较四个预先规定的动量窗口。数据、费用、目标仓位、验证区间和测试区间都固定。候选只能改变窗口，不能为了让某个结果好看而临时换数据来源、费用或标签。这样每个分数才具有共同含义。

## 验证集会被研究过程消耗
反复用同一验证段挑选候选，会逐渐适应该段噪声。即使每次都没有读取最终测试，研究自由度仍然在增加。因此评估日志必须保存全部候选，而不是只保留最好的一个。有限搜索预算和独立最终检验是共同需要的约束。

测试段保留在后面，先冻结窗口和其他配置，再计算一次。若结果不好，不应把测试反馈送回生成器继续优化同一测试；可以提出新研究，但需要新的独立证据。把“最终测试”写在变量名里，不会自动保护它的角色。

## 逐项理解评价计算
feature 是过去窗口收益，target 根据正负生成 0 或 0.5 的目标仓位。future 已按当前决策之后的一期收益对齐。traded 记录目标变化，net 扣除简化成本。这里仍是研究用价格区间计算，不等同于 AStock 的实际撮合账户；正式交易评估应接入真实可执行时点和规则。

validation 与 test 使用不相邻区间，中间留出一段隔离。标签跨度只有一期，空隙大于所需边界，便于直观理解。本例使用全历史特征计算再切片是允许的，因为特征只使用当前和过去；评价不能为了让测试期预热而读取测试后的未来。

## 内容摘要用于绑定配置
frozen 保存选定窗口、费用和区间，并计算 SHA256。摘要不是“策略有效证书”，它只帮助核对后续报告是否来自同一份配置。若你改变费用却沿用旧摘要，记录系统应重新计算而不是相信手工标签。

完整项目还应绑定数据内容、代码和算子库版本。否则同一个配置文件在不同数据上运行，结果仍然无法比较。摘要是追溯工具，需要与实际运行和数据证据一起保存。

## 结果不好时怎么反馈
给生成角色的反馈应具体，例如验证段净收益未超过基线、换手过高、有效样本太少或未来不变性测试失败。不要只给一句“继续优化直到盈利”，它会鼓励无限尝试并挑选偶然成功。

反馈也不应暴露冻结测试的详细结果用于下一轮参数搜索。如果当前测试被用来形成新想法，就在报告中明确它已经成为探索资料。后续研究需要新的测试边界，不能继续使用原有“未见”标签。

## 常见误差来源
选择区间时 Python 切片右端不包含终点，验证 [100,170) 有七十行。报告如果写成包含第 170 行，会造成样本数对不上。收益最后一行没有下一期标签，应该排除而不是填零。换手首行的建仓成本也应明确，本例通过目标变化计算，但在独立子区间中是否重新空仓需要单独约定。

当前代码在全序列上计算目标变化后再取区间，表示评价区间继承此前研究信号所形成的目标状态，而不是每段必定重新建仓。若需要每段空仓开始，应在切片后重算首期换手。两种口径都可研究，但不能在候选之间混用。

## 参数实验
保持冻结窗口不变，将费用提高一倍，只报告净收益变化，不重新选赢家。然后另开一个实验，允许重新在验证段选择，比较两个问题的差别：前者是成本敏感性，后者是另一套研究选择。

再将测试标签改成极端值，确认验证赢家不变。代码最后已经包含这一检查。它不能阻止研究者手动看测试，但能确认程序中的选择依赖没有越界。

## 读懂所有候选都亏损的结果
本课固定数据的一次运行中，四个窗口在验证段的平均扣费收益都为负，窗口五只是其中数值最高的候选。最优候选与值得部署之间没有等号。一个严谨的研究系统完全可以保留“选择结果”和“是否达到预设门槛”两个字段：前者总能按排序给出一个名字，后者可以拒绝全部候选。为了讲清选择流程，本例继续展示冻结测试，但不把它当成交易建议。

冻结窗口五以后，测试平均扣费收益约为负零点零零零二零七。它说明这组人工数据和成本规则下没有形成正的单期平均表现。不要立即改变窗口直到测试变正；可以先检查成本扣除位置、持仓是否使用了未来信号、样本是否足够，再提出新的研究问题。若这些实现都正确，负结果就应如实进入研究记录。

目标持仓在完整时间轴上计算，因此截取验证和测试区间时，第一天的换手可能延续前一天的目标状态。这适合解释“已有策略连续运行到此区间”的表现。若研究的是每个区间单独从现金启动，就应在区间起点重新计算首笔建仓成本。两种口径都可以定义，关键是不要把连续持仓口径的结果写成从零启动的账户收益。

候选摘要绑定的是规则与配置，不会自动绑定数据内容。若原始价格文件被替换而配置摘要不变，两次结果仍不可直接视为同一实验。完整记录应同时保存数据摘要、时间范围、费用参数、代码版本与候选清单。本例先演示配置冻结，毕业项目再补上数据与环境信息，让记录逐步变得完整。

自动化容易在几秒内试几十条候选。候选越多，验证段出现偶然赢家的机会越大，哪怕每条都没有稳定信息。可以做一次预先定义的对照：加入十条随机信号，使用同样排序规则，观察验证最好者到了测试是否维持优势。这个练习不是为了从随机信号里找赚钱秘诀，而是理解为什么需要记录失败候选与总尝试次数。

对评价程序本身，也可以构造答案已知的输入。全程零持仓应得到零毛收益与零交易成本；固定半仓在起点建仓后不应每天重复收取建仓成本；改变测试标签不应改变验证赢家。这些检查验证账目和依赖关系，通常比把某次收益的小数硬编码成标准答案更能发现真实错误。
