# 大模型能帮助哪些研究环节

## 把助手放在可检查的位置
大模型可以解释一段代码、把自然语言想法整理成研究假设、生成候选实现、总结实验结果。但它不天然知道你本机软件的真实接口，也不能仅凭语言流畅就判断一个策略有效。使用它最有价值的方式，是让每一步输出都能被代码、数据或来源核对。

你已经学过模型理论，容易理解生成文本是基于输入与训练形成的输出，而不是自动获得真实市场知识。量化场景的困难在于：一个听起来合理的解释，可能混淆信号时间、成交价格或财报可知时间。错误不一定表现为程序崩溃，反而可能产生漂亮的回测曲线。

## 三种适合入门的任务
第一是解释已有、可信的代码。把一段公式连同变量单位和频率提供给模型，让它解释每一步，再对照代码实际运行。第二是提出有限的、可检验的假设，例如五期与二十期动量在扣费后的差异。第三是审查结论是否超出证据，例如从合成数据的正收益跳到实盘盈利承诺。

这些任务都应有明确输入边界。不要在没有需要时把真实账户、个人信息或密钥贴进提示。课程默认使用人工数据和接口说明，能完整练习流程而不涉及实际账户。

## 离线演练到底是什么
上面的响应由课程作者编写，用来演示输入、输出与核验方式；它不是历史真实模型响应，也不是模型在当前运行中生成的新结果。mode 明确写为 offline-authored，real_model_calls 为零。这样即使没有 GPU 或 API 账户，你也能完成流程练习，同时不会把演练结果误记成真实调用成功。

离线样例的价值在于确定性：每次输出相同，便于测试后续解析、约束和评价。真实模型可能返回不同结构、代码围栏或额外解释，因此还要单独验证真实接入与错误处理。两种验收应并列记录，而不是相互替代。

不要将密钥写进 Notebook 单元或提交到报告。接口只从环境读取，不打印请求头；远程地址要求 HTTPS，本机回环地址允许 HTTP。默认每次客户端最多三次调用、每次超时最多二十秒，输出 token 和响应体大小也有限制。没有自动重试，避免网络故障造成不受注意的重复费用。

这些限制控制运行边界，不保证模型服务免费，也不保证不同服务完全兼容。首次真实实验应先用无敏感数据的短请求，检查状态与返回格式，再扩大任务。课程发布的离线测试不代表已验收你的本地服务或云账户。

## 真实响应也要先当作候选
模型可能给出不存在的指标函数、引用不真实的论文、把百分比与小数混淆，或者将未来收益当成特征。不要把它的输出直接写入运行中的策略账户。先保存为候选，检查语法、接口、数值样例和时间边界，再决定是否进入实验。

对自然语言结论也一样。让模型说明“依据哪张表、哪个区间、哪一项指标”，比让它泛泛评价策略更容易核验。若无法指出证据来源，结论应保留为待查，而不是因为写得像报告就接受。

## 如何设计一条有用提示
提供明确任务、允许的数据字段、已知接口、禁止使用未来数据的时间约束，以及期望输出结构。例如要求返回假设、公式、输入字段、决策时点、失效场景和需要验证的指标。不要只写“给我一个赚钱策略”，那既缺少可检验约束，也鼓励没有依据的收益表达。

输出结构化并不等于内容真实。合法 JSON 只能证明解析成功；字段中仍可能有错误公式或不合理窗口。后续两课会分别检查假设与候选表达式，评估部分由程序计算，而不是由模型自己宣布成功。

## 参数实验与记录
先使用离线模式完整运行，再修改一个响应，使其声称“当日收盘信号按当日开盘成交”，观察人工审阅是否能找出时间矛盾。然后把接口地址配置错误，在显式真实模式下确认错误被报告且不会无限重试。真实调用有可能收费，因此这个网络实验由你主动选择，不是课程自动运行的一部分。

## 把模型回答拆成四种可以分别验收的主张
假设回答写道：“用五日动量选股，先按当日收盘计算，再在同日开盘买入，因为动量通常能持续上涨。”这里至少包含四件事：五日动量公式、输入价格的可知时间、成交时间、关于未来延续的经验判断。公式可以用手算验证，时间顺序可以用索引断言验证，成交规则要由回测引擎支持，最后那句则需要样本外证据。不能因为第一件事正确，就把整段回答都视为可信。

给助手的资料也要附带版本。例如提供当前软件的策略接口名称、允许字段以及一个最小可运行示例，再要求只使用这些接口。若助手从记忆中写出另一个平台的函数，语法可能正确，运行时仍会失败。你可以先让它逐项列出所调用的接口及资料来源，再与本地说明对照，减少在整段脚本中定位不存在函数的成本。

真实接口配置前，先理解地址的组成：版本根地址加聊天完成路径组成最终请求地址。若根地址已经包含完整聊天路径，再由适配器追加一次就会请求错误位置。遇到连接失败时，依次检查地址、服务是否启动、模型标识是否存在和鉴权要求；不要一开始就增加重试次数。某些服务只支持不同的请求接口，本课程适配器不会自动替你转换协议。

同样，最大输出长度是请求约束，不是费用精确上限。服务可能采用不同计量方式，输入也可能计费。课程用短输入、最多三次调用、有限超时且不自动重试，让一次实验的边界清楚；你仍应在主动开启云接口之前理解该服务的计费说明。离线模式则完全不创建网络请求，可用它完成本模块的所有默认学习步骤。

记录真实调用时，不保存密钥和完整请求头，而保存服务类型、模型标识、调用时间、脱敏后的输入摘要、响应摘要、调用次数与错误分类。若模型返回解释但缺少所需结构，应该记作格式不合格；若请求超时，记作未取得有效响应。任何失败都不能被离线样例覆盖成“真实调用成功”。这个记录习惯会在后面的自动研究流程里帮助你区分模型问题、网络问题和验证器问题。

1. 不能，它只验证流程与解析，真实调用次数仍为零。
