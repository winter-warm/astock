# 代码生成与检查：把候选限制在能够验证的语言里

## 为什么本课不直接执行一整段生成脚本
模型能返回看起来完整的 Python，但其中可能有不存在的接口、错误的窗口，也可能包含文件、网络或系统操作。简单地把输出交给 exec，并不因为它来自“代码 agent”就变得可靠。本课采用一个更容易教学和核查的选择：模型只生成一个受限算子表达式，由我们自己的解释器执行已审阅计算。

这不是通用 Python 沙箱。它只接受两种形式：momentum(close,n) 和 reversal(close,n)，窗口为规定范围内的整数。你已经学过编译与语法相关基础，可以把它理解为一个很小的领域表达式语言。范围小，才能逐项说明允许什么、拒绝什么、实际如何计算。

## 语法树比字符串替换更明确
ast.parse 将输入解析为表达式语法树。我们检查根节点必须是调用、函数必须是允许的名字、参数数量必须为二、不能有关键字参数、输入字段必须是 close，窗口必须是 2 到 30 的整数。检查通过后，并不编译或执行原字符串，而是直接调用自己写的 pandas 公式。

因此导入、属性访问、下标操作、任意函数和嵌套代码都不在语言范围里。不能仅通过删除某些危险词来获得同样清楚的语义，因为字符串可以有多种写法，语法结构才决定它实际表示什么。

## 数值核验先用手算样本
价格 100、101、102、103 时，三期动量在第 3 行为 103/100−1=3%。代码用 np.isclose 检查这一点，再检查前面的预热区间保持缺失。对 reversal，结果应只是该动量取负，排序方向随之改变。

如果模型表达式语法合法，但你自己的算子实现错了，语法校验无能为力。因此必须分别测试：表达式能否解析、参数是否允许、公式是否正确、时间边界是否正确。把这些统称为“检查通过”而不分层，会让你不知道究竟验证了什么。

## 修改未来而不改变过去
我们把第 6 行之后的价格乘以十，比较前六行输出是否不变。动量只依赖当前与过去价格，所以应该相同。若某个新算子使用居中窗口、负方向 shift 或全样本归一化，就可能破坏这个性质。

该测试不是完整证明。例如源数据本身已经包含事后修订，单纯改未来价格未必能发现。它是重要的一层防线，需要配合输入字段可知时间、数据来源和人工公式审阅。

## 拒绝样例也要保留
bad 列表包含导入系统操作、负窗口、直接属性调用和布尔窗口。测试要求它们被拒绝，但不会真正执行其中的系统调用。这样的反例能帮助防止将来为了“支持更多表达式”而无意放宽约束。

注意 Python 的 True 在某些类型判断中会被当作整数一；本例明确检查 type(value) is int。窗口过大、表达式过长和未知字段也应给出具体错误。错误信息用于修正候选，不应自动把失败转换成默认公式再继续评估。

## 从表达式到可阅读的代码
当候选通过检查后，可以由可信模板生成完整说明代码，例如读取 close、计算窗口、保存分数和输出报告。模板由应用维护，模型只提供经过校验的参数。这样仍然实现了从自然语言到可运行研究代码的链条，却避免把所有执行权交给任意生成文本。

如果确实需要通用 Python 生成，应该转为用户审阅的独立脚本，明确依赖与数据路径，并在隔离实验中逐项检查。本课不把这个小解释器夸大为能安全运行所有代码的平台，也不把它接到真实订单提交。

## 按语法树逐层判断一条表达式
表达式“动量函数作用于收盘序列与窗口五”解析后，根节点是一条函数调用，函数名是允许名称，参数分别是序列名称和整数常量。验证器不需要运行它，就能检查这几个结构。随后程序用自己拥有的公式计算结果，模型提供的文本只承担选择操作符与参数的职责。这让候选表达式成为一段有限描述，而不是能够任意调用系统功能的程序。

看似相近的表达式可能有完全不同的行为。例如访问对象属性后再调用方法、在参数里嵌套另一个调用、使用关键字参数，或通过负号构造整数，都会产生不同的语法树节点。当前协议不需要这些形式，因此直接拒绝。拒绝负号节点并不是说负数在 Python 中不合法，而是我们的窗口定义只接受正整数常量，验证器没有理由扩大解释范围。

手算测试可以用价格一百、一百零一、一百零二、一百零三，窗口三时最后一个动量为百分之三。前面不足三期的部分应保持缺失，不能补成零后假装它们已经有历史。再把最后一个价格改成一百一十，早先时点的因子应保持不变。第一个检查公式，第二个检查时间依赖，两种测试覆盖的问题不同，都不能被“没有报错”替代。

还应检查索引保持一致。如果计算结果丢掉日期、重新排列行，数值本身可能正确，接回标签时却发生错配。执行器返回与输入对齐的序列，并保留预热期缺失位置，比返回没有索引的裸数组更容易追踪。多证券扩展时，还要明确分组边界，不能让一只证券的最后几行进入另一只证券的窗口。

本课的允许列表不是通用 Python 安全沙箱。它之所以容易审查，是因为根本没有执行候选 Python，只识别非常少的语法形状，再调用已有实现。如果以后允许赋值、循环、导入和任意函数，风险与验证复杂度都会发生质变；不能沿用当前几个检查就宣称任意脚本也安全。

参数实验可以分为两组：合法组比较动量与反转、窗口三与五的数值和预热长度；非法组尝试属性访问、字符串窗口、未知名称和嵌套调用，确认它们在计算之前被拒绝。把非法样例也保留为测试输入，未来扩展验证器时就能发现是否意外放宽了边界。
