# NumPy：给价格数据一个明确的形状

## 为什么从列表走向数组
前几课用列表保存价格，足以解释策略。但是，当你同时观察几百只证券、多个指标和很多日期时，嵌套循环容易把“哪个方向代表时间”弄混。NumPy 数组把数据类型和形状放到明处，让一次运算能作用于一整列或一整块数值。你已有 C++ 基础，可以先把它理解为带维度信息的数值存储，而不是把 Python 列表换个名字。

本课只讨论已经对齐、没有缺失的两只虚构证券。两列的含义固定为 A、B，三行的含义固定为先后到来的三个观察时刻。真实证券按日期对齐和缺失处理要到后面完成。数组本身不知道“交易日”或“股票”，这些业务含义必须由你维护。

## 从形状读懂程序
prices.shape 为 (3, 2)，表示三行两列。prices[1:] 取第二行至末尾，prices[:-1] 取第一行至倒数第二行，两者都是 (2, 2)。逐元素相除，再减一，就得到相邻观察值的收益率。A 的价格 10→11→12.1，两段都是 10%；B 的价格 20→18→19.8，分别是 -10% 与 10%。

这里除法是对应位置相除，并不是矩阵除法。不要因为看到二维数组就把所有运算理解成线性代数。乘号 * 一般逐元素运算，@ 才表示矩阵乘法或相应的向量内积。写程序前先在纸上标出每个维度的含义，再判断你要消去的是哪一维。

## 组合计算的含义
weights 长度为 2，分别给 A 和 B 分配 60% 与 40%。returns @ weights 将每个时刻的两只证券收益按权重合起来。第一段为 0.6×10%+0.4×(-10%)=2%，第二段为 10%。这只是“每段开始时都具有该权重、没有费用”的组合收益计算，不是已经实现了买卖和再平衡。若买入后完全不调仓，权重会随着涨跌变化，不能一直使用相同向量。

同样的数字能对应不同的研究问题。returns.mean(axis=0) 是沿时间方向求每只证券平均收益；mean(axis=1) 是每个时刻对证券取平均。axis 表示要被聚合掉的轴，不是结果保留下来的轴。试着手算第一行两个收益的平均值为 0，再和 axis=1 的输出核对。

## 广播：方便，也可能放大错误
将一个长度为 2 的数组与 (2, 2) 数组运算时，NumPy 可以按尾部维度匹配广播。这样不需要手写循环，但合法形状不等于正确业务含义。如果时间数恰好等于证券数，一个本来按时间准备的向量也可能被当成按证券应用，程序不会报错。不要让“成功运行”替代维度核查；变量名称、shape 断言和小样本手算应同时存在。

保留二维列向量时，形状 (n, 1) 与一维 (n,) 不一样。二者相减可能产生 (n, n) 的结果，而不是你想要的一列误差。后面机器学习课遇到预测值和标签形状时会再次用到这一点。当前阶段先养成打印中间 shape 的习惯。

## 视图与复制
代码后半部分故意修改一个视图。切片通常可以共享原数组的数据，因此 view[0,0]=99 会改变 prices。snapshot 使用 copy，保留最初的 10。研究中需要保留原始数据时，不能只更换变量名；同时也不必每一步都复制巨大数组。明确哪些对象允许修改，哪些对象是实验输入，就能兼顾可追溯性和效率。

本例 prices 使用 dtype=float，因为收益计算需要小数。不要向整数数组直接写入小数并假设它会自动升级精度。也不要把浮点金额和账户的精确记账混为一谈；本课数组用于研究计算，订单和账本继续遵循软件的金额规则。

## 参考答案

1. A 为 10%，B 为 0%；这是算术平均，不是两段累计收益，累计收益下一模块会细讲。
2. 后一段收益作用于更新后的资金，复利结果为 1.02×1.10−1=12.2%。
3. 输入已经变了，结果当然变化。因此代码把视图演示放在数值验证之后，正式研究应保留不可变原始副本。


## 再手算一次二维计算
把第一段收益写成一行 [0.1,-0.1]，权重写成一列 [0.6,0.4]。内积先逐项相乘得到 [0.06,-0.04]，再相加得到 0.02。第二段 [0.1,0.1] 对应 0.06+0.04=0.10。你应能指出每个元素属于哪只证券，而不仅复述“矩阵乘法得到组合”。

若你误把权重写成 [0.4,0.6]，第一段就变成 -0.02。形状仍正确，也没有任何异常，损益却反向。这说明标签核对和维度核对是两层不同验证。下一课的 pandas 标签对齐会减少这种风险，但也需要理解其规则。

## 行切片和列切片的具体差别
prices[:2] 选择前两行，保留两只证券；prices[:,0] 选择第一列，保留所有观察时刻。prices[0] 则是第一行，包含两只证券的初始价格。用一组不对称数字更容易暴露错误：如果所有价格都相同，转置以后看起来也相同，测试就没有辨识力。

尝试对三行两列的价格表做 transpose，形状变为两行三列。运算本身合法，但现在时间和证券的轴已经交换。如果后续代码仍沿原来的轴算收益，就会变成“证券 B 相对证券 A 的价格比例”，而非同一证券的跨期收益。打印轴的文字说明与 shape 一起保留，能让错误更早被发现。

## 数值类型的实验
将 dtype=float 改为整数再建立数组，包含 12.1 和 19.8 的输入会失去小数部分，之后收益当然不同。你可以观察 11→12 不再是 10%。正确选择不是见到错误后随意四舍五入，而是先明确研究数值需要的精度。处理证券代码则相反：它应保留为字符串，不应为了放入同一数组就强制转成浮点。

研究特征常用浮点数组，是因为滚动和统计计算方便；现金账本使用其他精度约定，是因为记账要求不同。两者之间的转换点应显式写出。例如打印收益时可保留四位小数，但不要在下一步复利之前把每天收益都截成两位百分数。

## 一次有目的的重构
你可以先写双重循环计算每个元素收益，再与向量化结果逐项比较。两者相同以后，再讨论向量化减少 Python 层循环开销的好处。若输入含零价格，分母校验应在两份实现中一致；不能一份抛错，另一份静默产生无穷值，然后只对正常样本说它们等价。

最后记录三个不变量：价格保持正且有限；收益矩阵行数比价格少一；每行组合计算使用同一证券顺序。它们不能证明策略盈利，却能清楚保护这个小计算的输入输出约定。

## 增加一个核对实验
核对维度时先写单位：行是观察时刻，列是证券，权重沿证券维相乘。若把时间维误当证券维，即使形状偶然相容，输出也不再具有组合收益的含义。
