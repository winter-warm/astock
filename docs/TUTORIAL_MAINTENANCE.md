# 教程随版本维护

教程是产品的一部分。修改按钮行为、菜单位置、表格字段、参数单位、策略 API 或课程代码时，同一批改动必须更新相应说明，并重新生成与当前源文件摘要对应的证据。单纯增加版本号不能让旧证据继续通过。

## 内容来源

- `src/astock/course_content/catalogue.json` 是资源总目录。应用量化课程仅展示稳定 ID q01—q72；操作条目是内部维护资料，不再混入学习目录。
- 三个 `catalogue-*.json` 文件分别维护连续课程链。`tools/merge_course_catalogues.py` 校验范围再合并，保留操作手册。
- 文章只通过 `{{code:示例ID}}` 引用 `examples/*.py`。阅读器与 Notebook 读取同一个文件，不能各维护一份相似代码。
- 每课 `check` 包含可确定判分的问题、可接受短答案和解释。阅读记录、自测通过、代码运行状态与旧四课实作分别存储。
- `interface_controls.json` 使用 `helpId`，不复用样式 objectName。循环生成的同类按钮可共享创建点，帮助同时展示实际按钮文字、字段名称、当前范围、表格列和页签。
- `onboarding.py` 是唯一面向用户的首次使用教程，首次启动自动展示，帮助菜单可重放。35 步按章节组织，每步有用途、操作与核对结果，必须指向当前实际控件。章节跳转只切页、切标签和高亮，不保存或启动业务；临时展开的运行控制在关闭引导时恢复。`operation_paths.json` 保留为内部核对清单。初始化必须单独确认、停止全部写入进程后才清理数据；保留学习状态和学习文件，不建立备份。

## 修改后的检查顺序

1. 按实际实现修订正文、示例和控制说明。新增可交互控件后运行 `tools/register_help_targets.py --apply`，再编辑 `tools/write_interface_help.py` 中该控件的用途、操作与条件。未匹配的条目仍是未复核状态，不能发布。
2. 运行 `tools/write_interface_help.py` 与 `tools/publish_interface_manual.py`，生成内部逐项核对资料。复核菜单、保存时机、数据单位及禁用条件；自动生成文章不代表内容已经正确。
3. 运行 `tools/register_help_targets.py --check`。工具扫描应用 Python 文件中的控件创建点；公共 Qt 控件工厂内部由调用处登记，原生工具栏溢出和停靠按钮在帮助层单独说明。
4. 在独立 Notebook 环境中安装锁定依赖。运行 `tools/verify_course_release.py --notebook-python <该环境的Python路径>`。它检查 72 课资源和自测、深浅主题/125%与150%/两种窗口大小、所有登记目标的实际创建、全量 pytest、Ruff，以及 72 个全新内核的 Notebook 执行。
5. 查看本轮截图和逐项报告，复核正文及代码的语义。逐步检查全部使用教程目标实际可见，章节切换不启动业务；特别核对待运行策略与当前结果来源、右侧参数检查、回测运行控制、模拟账户控制和归档报告的边界。所有报告对应同一个 source snapshot；验收期间代码或正文变化会使本轮证据失效。
6. 将真实报告路径和 SHA256 记录到 `docs/tutorial-release-baseline.json`，并写明具体复核范围与结论。基线不是测试工具自动生成的“全通过”开关。报告必须 `passed=true` 且 snapshot 一致。
7. 运行 `Build-AStock.ps1`。构建始终执行 `check_learning_content.py --prebuild`，`-SkipTests` 也不能绕过教程门禁。已有输出目录包含 `data` 时停止覆盖；使用 `-OutputDirectory` 指定新的项目内目录。
8. 运行 `tools/Test-Release.ps1 -ArchivePath <新zip>`。脚本在新的含空格目录解压，移除 PATH 中开发工具，以便携 EXE 验证课程进程、Notebook 导出、首次使用教程、初始化取消与隔离重置，以及回测、回放、权益、目录、规则、报告和四课流程。记录新包哈希与真实验收结果后，再运行 `check_learning_content.py --release`。

## 发布门禁为什么会拒绝

课程缺失、未发布、示例引用错误、题目不完整或正文过短都会拒绝。前六课按用户背景压缩；第七课起正文至少 2000 个汉字，代码不计入正文门槛。字数检查只排除过于单薄的文章，不能替代推导、易错点和实验设计的编辑判断。

源代码、资源、依赖锁、构建脚本或验收工具变化时，摘要与旧基线不符，必须复核受影响语义并重新验证。报告被改写、报告缺失、实际目标缺失或未覆盖，也会拒绝。更换版本号后复制旧 `passed` 标志不成立。

## 证据边界

Notebook 默认使用 CPU 与合成数据，AI 默认离线回放。它证明导出、依赖和示例执行，不证明模型盈利或真实 API 已连通。打包离线验收不包含付费模型调用、券商交易或盘中一小时实时稳定性；如单独执行在线验收，应另存当次证据，不沿用本轮离线结果。

软件内 Python 是独立工作进程，便于停止、超时与避免误用交易账户；它不是操作系统权限沙箱，只运行可信代码。修改后的草稿不会自动取代发行版示例，导出每次创建新目录，旧笔记保持可编辑。
