# AStock 数据包

一个数据包由同名的 `id.json` 和 `id.parquet` 组成。通过 `astock.datasets.write_dataset` 生成，数据中心选择 JSON 导入。不要手动修改生成的 Parquet；校验哈希不同会阻止使用。

0.1.6 增加可选 `coverage_request={"start":"YYYY-MM-DD","end":"YYYY-MM-DD"}`，也可提供含时区的精确时间，用于保留下载时请求的区间。没有这个字段时，只检查实际首末 K 线之间的覆盖，不能据此声称之前/之后完整。实际 `start/end/count` 会与记录重新核对，混合周期拒绝导入。

`quality` 保存 `coverage-v2` 的摘要、日历版本/哈希/来源、应有柱数和缺失数量；读取时重新计算，不信任手动修改的“无缺口”声明。完整诊断通过后台检查生成独立 HTML/JSON，逐项区分无记录交易日、连续缺失柱、未覆盖边界、停牌标记和不参与连续竞价的柱。统计以各证券和实际周期为单位，分钟首末部分交易日不凭空扩成整日；午休、周末和公告休市不计入缺口。v2 按 2026-07-06 生效日期处理沪市 ETF 收盘集合竞价，生效日后 14:57 结束的完整分钟柱可用，14:58—15:00 不作为连续竞价缺口。

交易所日历目前为 2023—2026 年，范围外明确列为未知；真实行情观察值超出范围会阻止回测。请求边界超出范围但实际观察值均在范围内时，仅提示边界未核验。合成教学包使用虚拟工作日日历，运行依据中单独标记，不能据其日期推断真实交易日。停牌字段存在的记录不再算“没有记录”，缺失本身也不自动改成停牌。

事件类型：

- `Bar`：symbol、含时区的结束时间、未复权 OHLC、成交量（股/份）、period、prev_close、factor，以及可选涨跌停价/停牌标记。`factor` 仅用于指标观察值，成交永远使用未复权 OHLC。
- `Quote`：来源时间与接收时间、最新价、买一卖一及数量、累计成交量、昨收与涨跌停价。采集到的快照不应标为完整逐笔流。
- `CorporateAction`：生效时刻、每股现金分红、送转后的份额倍数、稳定事件 ID、现金到账日期 `pay_date`、份额可卖日期 `share_available_date`。现金分红先形成应收权益，到账后进入可用资金。份额倍数不为 1 时必须提供可卖日期，不能默认等于除权日。

权益事件须使用含时区的除权日开盘前时刻，保证按此前持仓计算权益。日期字段须为 `YYYY-MM-DD`，不能早于事件日期。同证券、同事件编号的不同内容会被拒绝；相同事件重复输入不会重复登记或到账。按账户证券合计计算新增份额，部分成交拆成多个持仓批次不会凭空产生碎股；合计仍有非整数份额时阻止处理，需要准确到账资料。

0.1.4 在权益事件后撤销该证券的旧委托，并等待新的价格，其他证券的有效委托不因该事件取消。到账日没有观察数据时，在首次后续观察时结转现金；流水同时保留约定到账日与实际处理时刻。旧数据包的送转事件若缺少可卖日期，须补齐后再运行。

跨日因子变化必须有同一天的权益事件。权益缺失、重复/乱序时间、无效 OHLC、负成交量等会阻止回测。零值开盘价不能当作真实开盘价补齐。

分钟周期支持 `1m/5m/15m/30m/60m`，时间指整根柱的结束；起点按周期倒推。仅完整落在同一连续竞价时段且对齐周期的柱用于撮合与策略回调。包含集合竞价的 15:00 股票柱不会被截出一段虚构的连续竞价数据；可以保留展示，但不用于成交。11:30 的结束柱与 11:30 的即时快照含义不同。

以下仅演示格式，数据是人工构造：

```python
from datetime import datetime
from pathlib import Path
from astock.domain import Bar, CN, CorporateAction, dec
from astock.datasets import write_dataset

events = [
    Bar("510300.SH", datetime(2026, 11, 12, 15, tzinfo=CN),
        dec("4.00"), dec("4.10"), dec("3.95"), dec("4.05"),
        1_000_000, prev_close=dec("4.00")),
    Bar("510300.SH", datetime(2026, 11, 13, 15, tzinfo=CN),
        dec("4.05"), dec("4.15"), dec("4.00"), dec("4.10"),
        1_200_000, prev_close=dec("4.05")),
]
meta = write_dataset(Path("my-data"), "格式演示", events,
                     demo=True, source="manual-example", verified=True,
                     notes="人工构造；已确认该演示无权益事件。")
print(meta["id"])
```

`verified=True` 表示数据提供者已核对整个区间的权益记录，不是跳过校验的开关。真实跨事件数据应提供完整明细；首版不支持配股认购或零碎股份处置，需要这种处理的区间应排除或另行扩展模型。证券规则可通过 `rules={symbol: InstrumentRule(...)}` 明确提供，运行报告会保存规则版本。

导入外部数据前须统一成交量单位。当前锁定 AKShare 的腾讯日线 volume 已经是股，不应再次乘 100；东方财富相关历史接口以手返回，适配层转换为股/份。未来升级 AKShare 时必须重新核对单位并运行适配器测试。

## 历史证券状态与规则修订

证券规则在数据中心的“证券规则”窗口维护：选证券、填写起止日（均包含）、状态、可选涨跌幅/T+0 属性及来源，点击“检查并另存版本”。后台检查区间交叠、全部观察日覆盖及无限制状态与价格上下限的冲突。缺少权益资料的数据也能补充规则，但补充规则不会改变其权益未核对标记。取消或失败不会发布半份数据；原数据、原规则与已有回测保留。

编程导入可使用下例（状态完全是合成演示，不代表浦发银行真实历史）：

```python
from astock.domain import RulePeriod
from astock.rules import default_rule

rule = default_rule("600000.SH")
rule.history = [
    RulePeriod("2026-07-01", "2026-07-10", "人工构造测试", status="risk_warning"),
]
# 作为 write_dataset(..., rules={rule.symbol: rule}) 的规则参数。
# 2026-07-03 使用 5%，2026-07-06 使用 10%；日期之间不读取未来行情。
```

状态值包括 `normal/risk_warning/no_limit/suspended/unlisted/unknown`。`limit_rate` 为可选 Decimal 比例（如 `0.20`），风险警示和无限制状态自动计算，不再手工指定；`t_plus` 为可选 0/1，仅 ETF 可设 0。每个区间都须有非空 `source`，来源内容由数据提供者负责，软件不自动证明它与公告一致。未知日期阻止回测；停牌和未上市状态停止下单/成交。完整时间表保存在运行清单，策略上下文仅收到当前日期解析结果，不会收到未来区间。

修订版使用新 id，`parent_dataset` 保存原 id、行情哈希及原元数据哈希；行情文件逐字节保留。`rule_engine=cn-date-rules-v2` 记录日期解释版本。重跑旧数据包时使用当前软件的日期解释，旧运行记录不改写。

## 在线输入与回放时间

`Quote.time` 是行情源时间，`received` 是采集接收时间，`observed` 是可选的引擎观察时间。0.1.2 的在线账户自动填写 `observed`；回放用 `observed`（没有时用 `received`）作为当时的处理时钟，仍用源时间判断是否过期。不会用今天的墙钟判断历史快照，也不会抹去当时的排队延迟。

新快照包的 `ordering=arrival`：按输入顺序保存，允许源时间重复/乱序，由撮合器按在线时相同的规则忽略。接收/观察时钟倒退会阻止回放并提示检查。日线/分钟包仍按源时间排序并拒绝同标的重复时间。

在线账户的 `manifest.input_archive` 引用 `inputs/运行编号/` 下的不可变 Parquet 分块，包含各片段数量、SHA256 和清单版本。先写分块，再在 SQLite 同一个事务内保存账户和已使用的输入前缀。强制退出后只恢复已提交前缀；没有引用的片段不会重演。停止、退出或恢复后整理为数据中心可用的数据包；跨日权益未核对时阻止回放。若分块写入失败，账户进入错误状态，未归档输入存入 SQLite 的 `unarchived_input` 流水。

人工下单、撤单、暂停、恢复和停止的控制记录保存操作时间及已观察输入条数。数据包回放是重新执行选定策略；它不自动重演原账户的人工干预。比较这类运行时须同时检查控制流水。

## 当前证券目录

`data/securities.json` 的 `version=1`，按 `sh_main/sh_star/sz/etf` 分区保存 `source/refreshed_at/records/excluded_count`，每条包含标准证券代码、源名称、类别、板块、可用时的上市日期及行业。`attempts` 记录各分区最近刷新结果；部分失败不改变该分区原来的获取时间或记录，全部失败不改已有文件。`excluded_count` 记录明确排除的存托凭证及重复记录数，不代表上游之外缺失的证券数。

获取时间是本机访问时间，没有资料的字段为空，不从名称猜测 T+0、历史 ST 或停牌。沪深交易所当前列表不能证明给定历史日期的上市状态。0.1.12 起 ETF 名单直接来自 [上交所](https://etf.sse.com.cn/fundlist/) 和 [深交所](https://fund.szse.cn/marketdata/fundslist/)，股票资料来自 AKShare 的上交所及深交所列表接口；旧版新浪 ETF 缓存仍兼容读取，但不用于当日规则核对。代码边界核对来源：[上交所 689009 存托凭证上市公告](https://www.sse.com.cn/disclosure/announcement/listing/c/c_20201027_5242851.shtml)、[深交所含 302132 的样本调整公告](https://investor.szse.cn/disclosure/notice/general/t20250603_613877.html)。目录范围与撮合支持范围独立，未知规则仍拒绝从目录加入。

ETF 记录的 `etf_reference` 保存 `t_plus/limit_rate/source/observed_at/source_date`；分区 `evidence` 保存标准化观察值和九次响应的请求参数、条数依据、字节数与 SHA256。资料必须来自完整的一致名单，获取日期不是历史生效日期。

0.1.13 实时账户的 `live_rule_observations` 保存每次实际采用的当日观察值、目录摘要和来源；规则 `history` 只增加对应日区间，`known_from` 按中国日期保存实际启用的带时区时间。该字段随输入归档的数据包保留，回放使用引擎观察时间判断当时是否已取得规则；不会提前向策略提供后来取得的属性。历史规则编辑器保留此时间边界，旧版缺少 `known_from` 的规则默认空映射。


## 分钟下载来源与昨收参考

0.1.10 的下载元数据 `provenance` 按证券保存 `minute-bars-v2` 适配器版本、来源、接收时刻、原始窗口及条数、选中条数、排除的未结束柱数量、未复权标记、成交量单位、来源帧与参考日线帧的 SHA256，以及各交易日使用的参考日期/价格。新浪直接保留股/份；东方财富的手按 100 换算，不从表格数值大小猜单位。

`prev_close` 是当天固定参考，不使用上一分钟收盘，也不使用当日或未来日线收盘。参考必须来自已核对交易日历中的前一交易日；缺失时保留 0 并把数据标记为待补充，不能通过逐分钟移动涨跌停边界来继续回测。除权日（包括下载窗口首日）及跨缺失观察日期发生的权益事件均要求补充资料。

分钟数据默认新浪，也可显式选择东方财富；失败不会自动切换来源并隐藏错误。来源原始时间重复/乱序会报错，非整数或负成交量不会截断成可撮合数量。请求范围之外及下载接收时刻之后的未结束柱会排除，实际行情记录不填补、不重采样为秒线。保留的含集合竞价柱仍按证券规则排除撮合。

旧版由下载器产生的分钟包（来源 `akshare-eastmoney/akshare-sina` 且没有 v2 依据）禁止直接重跑，仍可进行数据检查和保留旧结果。用户自行导入并核对参考价的数据使用其明确声明的来源与规则。

来源说明：[AKShare 新浪分钟数据](https://akshare.akfamily.xyz/data/stock/stock_quote.html)、[AKShare ETF 分钟数据](https://akshare.akfamily.xyz/data/fund/fund_public.html)。文档返回量和接口可用性可能变化，运行清单保留实际版本与范围。

## 历史状态原始资料

规则修订版的可选 `rule_evidence` 按证券代码保存 `stock-status-baostock-v1` 资料：`basic` 为原始上市资料，`rows` 为逐日 `date/code/tradestatus/isST`；另存请求范围、来源、收到时间、提供器版本、原始结构内容 SHA256、日历版本、建议区间和缺失日期。哈希针对适配器返回的结构内容，不代表 HTTP 或 socket 原始字节。

`applied_without_edits` 表示最终区间是否与留存资料重新计算的建议区间一致。手工修订不会伪装成接口原样结果，也不会删掉原始证据。此资料不修改原始 Parquet 价格，不更改权益事件核对状态。缺口报告 `coverage-v3` 结合有来源的整日停牌/未上市区间排除不应存在的柱，状态未知仍提示核对。

## 长期课程本地记录（0.4.0）

Store setting `learning_library_v1` 以稳定课程 ID 保存：`bookmark` 为书签，`position` 为正文滚动位置，`read_digest` 为已读内容摘要，`check_digest` 为已通过知识自测的内容/题目摘要，`drafts` 按示例 ID 保存代码，`last_run_status` 只记最近运行状态。`_last` 保存最近选择。旧版单个 `draft` 在首个示例中兼容读取。正文或题目摘要变化后提示复习，不删除旧记录。

这些字段与原四课实作、QMT 八课自测互不替换；运行成功不写知识题或实作通过。练习进程在 `learning/labs/<唯一ID>` 写本次 `exercise.py`。Notebook 导出位于 `learning/notebooks/AStock课程-<唯一ID>`，保留独立代码、锁定环境和课程清单；每次新建目录，不覆盖用户笔记。应用升级只替换安装资源，学习记录仍在原 data 目录。

## 0.5.0 首次操作引导与初始化

`onboarding_v1` 记录使用教程的 completed/skipped 状态和跳过步骤，独立于课程进度。首次启动自动展示，帮助菜单可重放。

初始化必须先关闭窗口、后台进程和数据库连接，再处理独立数据目录；不创建备份。保留 `learning_library_v1`、`course_practice_v1`、`qmt_course_v1`、`lessons_completed` 及 learning 目录，清空其他设置、策略、账户运行、流水和数据目录中的其他文件。旧学习记录保留用于兼容，不再作为公开课程入口；公开学习页仅显示 q01—q72。初始化后重建默认教学数据，并重新展示使用教程。


## 0.6.0 启动与工作区状态

正常启动使用当前用户范围的单实例检查，重复从不同安装目录打开时请求已有窗口回到前台；快捷方式指定 `--data-dir` 也遵守此规则。仅验证模式或测试专用 `--isolated-instance` 按数据根目录隔离。实例锁位于系统临时目录，不属于应用初始化清理的数据；进程退出或崩溃后可重新取得。

历史回测与快照回放、实时仿真与手动练习分别保留当前选择。账户与记录是独立只读选择，不会因为查看档案而改变当前正在控制的账户。回测准备显示当前草稿及参数摘要；已经创建的运行仍以自己的源码、参数和运行依据为准。
