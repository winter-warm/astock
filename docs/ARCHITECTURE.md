# 架构与开发说明

当前发布整理版本 0.6.1，核对日期：2026-11-15。交付、入口和用户数据目录见 [项目当前状态](PROJECT_STATUS.md)。下文描述当前源码；旧模块和版本号用于说明兼容范围。

## 工作区、引导与课程

`window` 用唯一左侧导航组织“写策略、历史回测、模拟交易、数据中心、账户与记录、量化课程”。`strategy_editor_window.StrategyEditorWindow` 现作为内嵌页面使用，中央直接编辑源码；`model_browser` 位于“模板与已存策略”对话框。主导航和“去回测”只切页，不隐式保存草稿、创建运行或下单；参数控件沿用同一状态，切换页面时不会打开空参数 dock。

`backtest_workspace` 使用同一运行快照显示价格、买卖点、净值、回撤和绩效，复用既有诊断、对比与报告模块。`model_trading` 展示策略账户及创建流程；准备与执行仍交给引擎。`qmt_workspace.build_market` 构造数据中心的历史数据列表和实时行情标签，复用下载、导入、规则及质量检查；模块名不代表公开的 QMT 课程页面。

`account_overview` 按账户读取已保存记录和当前状态，显示资金、持仓、最近操作与日志；所选账户存于 SQLite 设置 `home_account`。查看或切换账户不恢复策略，历史估值时点随快照显示。

`course_library` 读取同源课程目录和示例；公开“量化课程”页筛选长期课程，共 12 模块、72 课。`course_ui/course_reading` 提供搜索、目录、书签、阅读位置、独立草稿与知识题，状态存于 `learning_library_v1`。旧四课 `course_practice_v1`、QMT 八课 `qmt_course_v1` 等状态兼容保留，但旧课程和任务目录不再列为公开入口。正文摘要变化会提示复习。

`course_lab` 用 spawn 独立进程运行普通练习，每次生成独立工作目录，支持停止、30 秒超时和 256 KiB 文本输出上限；`course_display` 显示受限表格与曲线。策略示例载入新教学副本后进入写策略页，并由既有引擎执行。`course_notebooks` 从相同正文和示例导出 Notebook，复制独立 CPU 环境和锁文件，每次建立新目录保留旧笔记。练习子进程不是权限沙箱。

`onboarding` 负责首次启动的 35 步、7 章节高亮教程；只切页、定位目标和解释操作，可跳过或完成。“帮助 → 使用教程重放”再次打开它。`help_registry/help_controller/control_help` 继续提供底层控件登记与说明能力；公开帮助菜单已精简为使用教程重放、初始化应用和关于，不再把旧手册、任务目录及四课入口混入菜单。最终源码的四组界面矩阵均通过，每组覆盖 78 个页面状态和 259 个登记控件。

`app_reset` 只在用户确认后请求关闭窗口；后台任务及数据库关闭后，初始化独立数据目录，再由 `app` 重新建立窗口。删除策略、账户、流水、行情、报告和设置，不创建备份；保留学习设置及 `learning` 目录中的内容。模块拒绝程序/源码目录及经过符号链接或联接的数据根。它与版本切换、清理旧程序的维护操作分开，本次同步不调用初始化。

`tutorial_release` 对源码、课程资源、测试、工具、锁文件和指定文档计算摘要；基线将语义复核及报告哈希绑定到摘要。当前发布报告路径由 `docs/tutorial-release-baseline.json` 绑定；0.4、0.5、0.6 的旧报告保留为历史，不能代替 0.6.1 结果。构建 `--prebuild` 与最终 `--release` 分别核验预构建和便携证据，`-SkipTests` 不绕过门禁。最终源码的 619 项回归与 Ruff 已通过；当前轮 72 个 Notebook 均已使用独立内核执行通过。便携包和发布结果见 Release 及源码附带的最终报告。范围见 [验收记录](VALIDATION.md) 和 [教程维护规则](TUTORIAL_MAINTENANCE.md)。

`app` 在 Windows 设置稳定应用标识 `AStock.Workbench`，并从资源根目录载入 `assets/astock.ico` 为 Qt 应用图标；冻结包同时包含该资源和 EXE 图标。窗口及任务栏据此获得一致的应用身份。

## 0.6.1 的数据语义与工作区隔离

`data_identity` 为数据选择、图标题、结果、归档和报告提供一致来源标识，区分真实历史、真实行情录制、合成教学及真实性待核对。来源标识不替代权益和规则完整性检查。`datasets` 的自然教学 K 线由固定种子日内路径生成，旧样本和既有运行哈希保留。

`domain/rules/broker` 将指数作为研究点位序列；引擎允许指标与信号计算，Broker 拒绝指数买卖。指数价格不产生账户分红或送转。`engine` 的速度仅影响快照回放等待，K 线模式不使用该等待参数。

`backtest_setup/backtest_workspace` 显示当前草稿、参数和待运行数据；已生成结果使用自己的运行快照。历史与模拟账户身份独立，异步创建、状态和错误回报按目标账户处理。`account_overview/report_jobs/reports` 负责归档和一致快照导出，查看记录不重新启动策略。

策略接口说明是独立只读窗口。回测设置可从 K 线、快照或尚未选数据的状态打开，保存才应用；取消保持原配置。资金上下限在各入口一致，数据动作随选择状态启用，视图菜单按当前页面恢复布局与说明区域。

本机真实行情位于用户 data，公开包只收代码、课程和必要说明，不收账户数据库或本机行情验收集合。`AStock.spec` 与源码归档范围在发布前核对。用户数据初始化与发布清理分开，本次不初始化、迁移或备份根 data。

## 进程与数据流

Qt 界面进程只负责交互、读历史结果和绘图。独立行情进程每轮请求指定证券，标准化为 Quote 后发给界面和引擎。引擎进程是每个虚拟账户的唯一写入方；用户策略在独立子进程中，通过 Pipe 收到截至当前的观察数据、账户只读副本和订单回报，返回下单/撤单指令及解释日志。

引擎先撮合前一时刻提交的委托，再调用策略；新指令不能在当前行情回填成交。回测与回放按时间分组处理多标的，策略只看到已处理观察值。历史观察窗口最多 2048 条。默认单次用户回调限时 2 秒，初始化进程加载最多 15 秒。

Broker 为每次订单状态变化保存独立快照，Run 按队列顺序投递 `on_order`；同一柱内先部分成交再撤单时，两次回报都会保留。回报生成的新指令不能越过已经排队的状态通知。连续回报最多处理 100 次，超过后终止该策略并撤单；异常不会让单步运行自动变成持续运行。

历史回测/回放暂停只冻结推进，保留订单和冻结资金；实时模式暂停会撤单。暂停/停止的订单回报允许更新策略内部状态和记录解释，回调中的交易指令被忽略。解释信息在策略进程中验证可持久化后才发给引擎，避免无效日志对象破坏账户保存。

```text
腾讯报价 / Parquet历史 → 标准化行情 → Broker撮合与账户 → 策略子进程
                                      ↑                 │
                                      └── 订单/撤单指令 ─┘
                                              │
                                   SQLite事务 → Qt界面/报告
```

## 存储

- SQLite WAL：设置、已保存策略、运行清单、完整账户快照和执行流水。展示的运行状态先持久化再发送到 UI；0.5.0 在入队前冻结消息快照，避免异步序列化把旧状态改写成后续成交状态。
- Parquet：每行保存时间、证券、事件类型和可无损恢复 Decimal 的 JSON 事件。文件 SHA256 随元数据保存。元数据保留来源、合成标识、覆盖范围和规则。
- 录制：每轮独立 Parquet 分块，先写 `.partial`，成功后替换；写入者持有操作系统文件锁，进程中断后自动释放。停止只封存分块数并释放锁，不在采集进程合并。后台整理取得同一锁后流式校验、保留接收顺序、重复与乱序；以目录生成稳定数据编号，先发布 Parquet，再发布 JSON，最后标记完成。中断后按分块指纹和目标哈希核对再续办；不覆盖不一致文件，不删除原始分块。批量取消保留此前已完成的目录。0.1.6 及更早的写入者没有文件锁，升级前须退出旧版；兼容读取旧完成标记。
- 报告：独立进程用只读 SQLite 单行查询固定 manifest/snapshot/result；不经过 GUI 传输大快照。完整 HTML、CSV、JSON 先写私有暂存目录，GUI 仅接受当前任务回报，以目录重命名一次发布到独立导出编号；取消和过时回报不发布。快照含读取时间、观察时间及内容哈希。运行对比在一个只读事务内提取所需字段，以按需绘制表格显示；坏记录隔离、结果可刷新。报告与对比都不暂停引擎。

SQLite 表结构版本仍为 1。0.1.4 的账户快照新增 `equity_ledger_version=1`、事件定义、不可变 `EquityEntry` 流水及持仓批次 `available_from`。缺省批次字段兼容旧账户；旧账户已发生权益事件但缺少流水时，只恢复查看并明确标记无法核对，不能用推算差额伪造过去的分红记录。

`accounting.reconcile` 用成交和权益登记/到账重建现金、应收、证券数量、持仓成本、费用及已实现盈亏，检查重复、冲突和提前到账。`Run` 将权益通知与账户快照写入同一 SQLite 事务，UI 和 HTML/CSV 展示同一流水。恢复核对失败的账户标记 `RECOVERY_ERROR` 并保留原余额证据；单个损坏账户不会阻止其他账户和引擎启动。

## 主要模块

`domain/rules/broker` 定义模型和无 UI 依赖的交易规则；`strategy/engine` 管理策略与运行；`market/datasets/storage` 管理数据；`window/ui_components/learning` 提供工作台与教程；`validation/reports` 产出验收证据。

兼容模块 `equity_lesson` 按需创建独立的合成权益练习及注释策略；旧四课入口在 0.5.0 不再公开。界面保存用户当前编辑后载入练习，单步操作使用真实引擎进程；不在界面中直接改账户。`WorkspaceStack` 以当前页面的最小可用高度布局，分析区不足时滚动，顶部模式与主操作保持可见。

`data_jobs` 为预览和导入启动可取消的独立进程。预览以 2,048 条为一批读取 Parquet 并执行完整校验，只向 GUI 返回最近 1,000 个图表点。GUI 用任务标识丢弃过时回报；取消或关窗会终止对应进程，并在其退出后清理私有临时文件。导入先复制到临时目录，通过全部校验后由 GUI 发布 Parquet、最后发布 JSON 元数据；现有同编号数据不替换。

订单与成交表使用 `QAbstractTableModel` 保留全部记录、按可见行格式化，避免创建大量单元格对象。一个消息轮询周期只绘制当前账户的最新状态；输入归档清单在界面显示条数、片段数及版本摘要，完整片段列表仍保存在数据库和导出快照。

早期成交定位复用数据准备进程：历史模式扫描已校验的数据包，在线模式读取已提交的输入前缀，取成交前后各最多 40 条同标的观察值。返回的图表数据不超过该账户当时的处理时钟；必须存在准确成交时刻，否则显示错误。分析区间保持固定，不随账户更新跳回最新行情，用户可主动返回最新视图。

QMT 行情仅保留 `MarketProvider.quotes(symbols)` 兼容接口，尚未实现连接，不显示为已可用来源。真实券商下单不在首版范围内。

`catalog/catalog_ui` 提供当前证券资料及搜索窗口，复用 `DataJobs` 的独立进程、取消及任务标识。四个资料分区逐个获取，单次请求设连接/读取超时，窗口另设 90 秒整体上限。仅完整验证成功的分区替换旧资料；GUI 接受当前任务结果后，写入同目录临时文件并同步，再原子替换 `securities.json`。全失败、取消和旧任务回报不会覆盖可用文件。目录与 Broker 规则隔离，当前名称、上市日期不注入历史撮合规则。搜索表使用 Qt model/proxy，兼容全角字母和证券名称内空格，关注列表独立保存于 SQLite 设置。

`trading_calendar` 保存有公告来源的日历，区分开市、休市及范围未知。`data_quality.CoverageScan` 流式记录各证券/日期的分钟位图，结合请求或实际边界计算缺口；正常预览/运行只保留摘要，明细检查才生成全部区间。后台质量任务还生成 HTML/JSON 暂存文件，GUI 仅发布当前任务成功结果。取消/关闭清理私有暂存文件，不改行情包。`Broker` 与策略回调使用同一交易日日历，教学虚拟日历作为显式账户字段保存与恢复；每次 `Run.manifest` 留存日历版本和数据覆盖摘要。

Windows 打包使用 PyInstaller onedir。工作进程通过 `multiprocessing.freeze_support()` 启动，策略源码作为运行清单保存后在子进程编译执行。仅需内置库及已打包的 NumPy/Pandas；额外第三方库需在源码环境安装并重新打包。

## 在线输入版本与崩溃边界

旧版实作兼容模块 `learning_guide` 用独立教学副本和短快照数据驱动真实策略/交易进程，不在界面伪造订单或成交。课程尝试标识随运行清单持久化，界面仅接受绑定账户的回报推进实作步骤；点击已读不推进实作。参数修改与保存、完成回测、成交图表定位、收到公开报价、账户停止分别记录证据。进度保存在 SQLite 设置 `course_practice_v1`，重做保留上次完成证据，重启不自动运行。第四课离线分支使用明确标为合成的回放，与在线连接记录分开。展开课程临时收起面板，离开学习页或关闭软件前恢复原布局。

`InputArchive` 在引擎进程收集每个账户实际观察到的报价，包含引擎处理时间。持久化时先写入并同步不可变 Parquet 片段，再由 SQLite 事务一起保存账户快照、输入前缀和事件流水。恢复不扫描或重放整个目录，只引用数据库已提交的片段，旧委托仍取消。结束时按该前缀整理为可回放数据包。输入保存失败时账户停止，未归档输入写入 SQLite 备用流水。

快照回放按接收顺序推进，沿用原始处理时钟来判断新鲜度与下单时刻；源时间重复或乱序的输入交给同一个 Broker 过滤。操作控制保留在原账户流水，数据包不自动重演手动下单及暂停操作，因此有人工干预时不能只凭同一数据包推断完全相同的策略结果。
